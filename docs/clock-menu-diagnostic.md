# 时钟菜单光标诊断

诊断版本不会自动注入左键或 Ctrl。每次打开菜单读取安装目录下
`clock-menu-diagnostic.txt`，无需重启应用：

| 文件内容 | 光标 | 原生菜单 300ms 时钟悬停守护 |
| --- | --- | --- |
| `legacy`、文件不存在或内容无效 | 原两段式移动 | 开启 |
| `nomove` | 不主动移动 | 开启（用于隔离守护影响） |
| `nomove_noguard` | 不主动移动 | 关闭，仅记录进出时钟区域 |

Tauri 备用菜单同样遵循光标模式，但原本没有此原生守护。
模式在一次菜单期间保持不变。旧菜单的守护线程不能跨会话干预新菜单。

日志沿用 `D:\agents_tmp\menu_dbg.log`：

- `ccm cursor diagnostic v1`：模式、注入开关、右键落点。
- `menu before TPM`：弹菜单前实际光标坐标。
- `menu hover diagnostic`：进出时钟区、坐标及经过时间。
- `menu hover guard`：旧守护主动关闭。
- `native dismiss: outside-down`：菜单外按下关闭。
- `native dismiss: item-up`：钩子路由菜单项。
- `native: TPM`：系统菜单返回值及持续时间（取消不能仅凭返回 0 判定具体原因）。

验收对照三种模式，覆盖快速右键、长悬停后右键、菜单打开后原地停留、
移出再移回、设置与退出、退出后桌面图标单击、桌面日历 owner=0。
截图只能证明拍摄时刻的可见状态；合成输入通过不替代用户真实操作验收。

当前属于诊断阶段；不应把“不移动”直接等同于 tooltip 已彻底解决。
恢复原行为：将文件内容改为 `legacy`。

## 连续右键失效修复

用户实测数次后菜单不再出现。日志显示右键均被接收，但 TPM 连续在数微秒内
返回 0。发现菜单属主被全局缓存，而调用者是可能跨 await 迁移线程的异步任务。
修正为每次菜单在当前线程创建属主、结束时同线程销毁，全局句柄仅供钩子取消
当前菜单使用；退出时清空菜单矩形。增加属主线程 ID 和 TPM 错误码日志。

修复版验证：连续 8 次右键均有一个可见原生菜单，4 次移出移回仍可见；
截图确认菜单完整显示，光标保持 `(3750,2115)`。设置操作后再连续右键 3 次
均通过，退出正常。菜单返回的错误码均为 0。构建与安装产物 SHA256：
`A98D754853C4D4781B56B12FBFE5C9F04ED3B6580D3C162BD0417A06DF0B4F53`。
以上为合成输入验证，用户长时间真实操作仍是最终验收。
